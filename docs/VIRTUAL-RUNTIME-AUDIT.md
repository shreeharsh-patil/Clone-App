All source-based virtual engines share the host UID at the kernel boundary. User-space path/UID hooks do not create separate Android security sandboxes. Hook startup, Binder proxy overhead, native ART coupling, crash recovery and guest trust require measurement in the integrated app. No performance or security certification is inferred from source availability, a linker flag, an upstream APK build or a README.

## Selected fallback

No candidate passed both legal/provenance and technical gates in this review. The task explicitly allows a smallest genuine guest-hosting prototype in that situation. This branch implements an original **cooperative first-party Activity host**, rather than importing an unresolved engine or activating the old placeholder.

It executes `org.parallelnest.probe.GuestProbeActivity` from the copied, signature-checked APK. The APK is not renamed, rewritten, re-signed by the host or installed as another system package. Only the first-party probe signed with the host identity is admitted. The Activity's actual content, callbacks, files, preferences and SQLite execute in a host subprocess. Other apps are rejected before registration.

This fallback is **not a completed arbitrary Android app virtualization system**. General Binder components, native/split guests, guest hardware bridges and third-party compatibility remain blockers. See [architecture and API limits](VIRTUAL-RUNTIME.md) and [recorded compatibility](VIRTUAL-COMPATIBILITY.md).
