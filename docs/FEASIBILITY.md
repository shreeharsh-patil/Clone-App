# Feasibility and source review

Research snapshot: 13 October 2026. Repositories were cloned with `git clone --depth 1` and their actual source/build files inspected. This is a source review, not a claim that upstream engines were built or tested. No upstream cloning engine code is incorporated.

## Decision

Use an original Android DevicePolicyManager profile-owner implementation. Android creates an independent user sandbox, UID, app storage and account namespace. The APK binaries may be shared by the platform, while their persistent private data is separate. This supports **one extra copy of a package**, not unlimited instances. Proof must use the first-party isolation probe and recorded device execution.

Use PackageInstaller sessions including base APK and split APKs. `DevicePolicyManager.installExistingPackage` requires affiliation in secondary/managed users, so it is not a general solution for an ordinary personally owned phone without a device owner. `enableSystemApp` is limited to system packages. Installation requests explicitly require user action; a DPC can have platform-granted installation privileges, but the user's selection and confirmation always precede the request.

No virtual engine passed the legal, maintenance, compatibility and security gates. The virtual-engine capability is compile-time disabled and the UI explains why. There is no substitute that merely renames shortcuts.

## Security review and boundaries

The work controller receives the bridge secret only via Android's provisioning admin extras. Each profile stores it encrypted using its own Android Keystore AES-GCM key. Requests authenticate the entire operation, package, paths, name, nonce and timestamp with HMAC-SHA256. The work activity also checks the callback PendingIntent creator package/application UID. Timestamp bounds and persistent nonce replay rejection prevent stale/repeated commands. There is no trust-on-first-message key initialization.

The personal app only resolves Android's `ForwardIntentToManagedProfile` component, never an arbitrary third-party activity advertising the same action. Replies also authenticate nonce, success, message, profile and app lists using HMAC before a pending operation may complete, so an app advertising the same work action cannot forge a successful reply with the passed callback capability. System provisioning receivers require `BIND_DEVICE_ADMIN`; installer callbacks and manager result receivers are private. The receiver refuses commands outside a managed profile owned by this app. Selected APK paths are canonicalized and restricted to platform package directories; the archive package must match the selected package. Split-file installation remains subject to PackageInstaller signature/split validation. There are no filesystem hooks, hidden API bypasses, root commands or Integrity/DRM evasion in the application.

This bridge permits launching and modifying installed work applications at the manager user's request. It is not a broad cross-profile file-sharing policy. The work profile still depends on the device manufacturer's Android implementation. No external library can turn an in-process virtual host into a stronger isolation boundary than the host itself.

## Official API references

- [Work profiles](https://developer.android.com/work/managed-profiles) and [build a DPC](https://developer.android.com/work/dpc/build-dpc): managed-user feature checks, OS provisioning consent, owner callback, setProfileEnabled.
- [DevicePolicyManager](https://developer.android.com/reference/android/app/admin/DevicePolicyManager): isProvisioningAllowed, addCrossProfileIntentFilter, installExistingPackage affiliation restriction, setPackagesSuspended. Required provisioning/compliance activities are provided. No wipeData operation is implemented.
- [LauncherApps](https://developer.android.com/reference/android/content/pm/LauncherApps), [UserHandle](https://developer.android.com/reference/android/os/UserHandle), [UserManager](https://developer.android.com/reference/android/os/UserManager): profile-specific activity discovery and persistent serial identifiers; paused/removed profiles must be accounted for.
- [Package visibility](https://developer.android.com/training/package-visibility): intent-scoped launcher discovery. No QUERY_ALL_PACKAGES permission.
- [PackageInstaller](https://developer.android.com/reference/android/content/pm/PackageInstaller): complete split session, system installation validation, user-action callback, uninstall in current profile only.
- [Application sandbox](https://source.android.com/docs/security/app-sandbox): private storage separation. Manager can report its own usage; third-party private/cache size requires Android app settings or supported usage authorization.
- [Background activity security](https://developer.android.com/guide/components/activities/secure-bal): a foreground work-operation Activity handles user consent. Terminal PackageInstaller results use a private broadcast PendingIntent and require no background activity launch. If the consent host is unavailable, the request fails explicitly and its pending session is abandoned.
- [16 KiB page support](https://developer.android.com/guide/practices/page-sizes): NDK ELF segment alignment and APK alignment must both be checked.
- [Notification permission](https://developer.android.com/develop/ui/views/notifications/notification-permission): each profile app manages its own runtime permission. No manager notification mirroring/fabrication.
- [Android 16 behavior changes](https://developer.android.com/about/versions/16/behavior-changes-16): edge-to-edge/insets and activity starts require testing, not an obsolete target SDK.

## Release gates still requiring evidence

Stock-emulator tests establish only their recorded configuration. A stable release requires physical ARM64 testing, at least one OEM build, Android 13/14/15/16 provisioning/lifecycle cases, notification/sign-in compatibility for each claimed third-party app, and startup/memory/battery measurements. Three independent virtual instances are not supported or claimed. No popular third-party app has been bundled or declared universally compatible.
